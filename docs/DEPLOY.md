# Запуск MBS Quality на сервере (Windows)

Всё ниже — дополнение. Прежний способ (`npm run dev` в `server` и в `client`) продолжает
работать; переходить на рабочий режим можно, когда удобно.

## Рабочий режим: что это и зачем

| | Раньше (`npm run dev`) | Рабочий режим (`start-mbs.bat`) |
|---|---|---|
| Страницы | сервер разработки Vite | собранные страницы (`client/serve.js`) — быстрее, меньше памяти |
| Если процесс упал | остаётся выключенным | «сторож» перезапускает за 2–30 с |
| БД недоступна при старте | сервер завершается | сервер пробует снова, пока БД не появится |
| Журналы | только в окне | файлы `logs\server-ДАТА.log`, `logs\client-ДАТА.log` (30 дней) |

Порты прежние: страницы — **30000**, API — **40000**. Адреса для ТВ не меняются.

## Первый запуск

1. Закройте окна, где сейчас запущены `npm run dev` (иначе порты 30000/40000 заняты).
2. Убедитесь, что в `server\.env` заданы `BRIGADE_PASSWORD` и `IMPORT_PASSWORD`.
3. Запустите `start-mbs.bat` в папке проекта (двойной щелчок).
   При первом запуске он соберёт страницы (1–2 минуты), затем откроет два свёрнутых
   окна: **MBS server** и **MBS client**.
4. Проверьте: страницы — `http://localhost:30000`, состояние — `http://localhost:40000/api/health`.

Остановить: закрыть оба окна (MBS server и MBS client).

## После обновления кода (git pull)

1. Закройте окна MBS server и MBS client.
2. Если менялись страницы — запустите `build-pages.bat` (пересобирает `client\dist`).
3. Запустите `start-mbs.bat`.

ТВ получат новую версию при следующем обновлении страницы; если ТВ держит старую версию
и она не загружается, страница сама перезагрузится через 10 с.

## Автозапуск после перезагрузки сервера

Сервер принадлежит IT-отделу, поэтому варианты зависят от прав:

**С правами администратора (сделать может IT)** — задача в Планировщике, запуск при
старте Windows, без входа пользователя:

```
schtasks /Create /TN "MBS Quality" /TR "\"C:\путь\к\проекту\start-mbs.bat\"" /SC ONSTART /RU SYSTEM /RL HIGHEST
```

Node.js должен быть установлен для всех пользователей (обычная установка).
Если IT предпочитает службы Windows, подойдёт NSSM — две службы:
`node.exe C:\путь\к\проекту\run\supervise.js server` и `... supervise.js client`,
рабочая папка — папка проекта.

**Без прав администратора** — ярлык на `start-mbs.bat` в папке автозагрузки
(`Win+R` → `shell:startup`). Запустится после входа в Windows под вашей учётной записью.

## Журналы

`logs\server-ГГГГ-ММ-ДД.log` и `logs\client-ГГГГ-ММ-ДД.log` — всё, что выводят сервер и
страницы, со временем каждой строки; строки `[сторож]` — запуски и перезапуски.
Хранятся 30 дней (`LOG_KEEP_DAYS`).

## Состояние системы

`http://<сервер>:40000/api/health` — работают ли БД (main, LES, MES, notes, BMS), связь
с ПЛК, когда сохранён последний снимок DRR по каждому чекпоинту, последнее резервное
копирование. `"status": "ok"` — всё в порядке, `"degraded"` — есть неполадка (смотрите,
где `"ok": false`), `"down"` — не работает основная БД или LES.

## Страница администратора

`http://<сервер>:30000/admin` — по специальному паролю (`IMPORT_PASSWORD`). В браузере
пароль помнится до закрытия вкладки. Только просмотр, обновляется каждые 30 с:

* **Состояние системы** — базы данных, связь с ПЛК, снимки DRR по чекпоинтам.
* **Резервные копии** — включены ли, когда и с каким результатом была последняя.
* **Использование страниц** за 7/30/90 дней — сколько раз и со скольких компьютеров
  открывали каждую страницу; список страниц, которые не открывались. Без имён: компьютер
  хранится как обезличенный код. Данные — в `server\data\usage.json` (400 дней).
  Страница, открытая весь день на ТВ, считается одним открытием.
* **Медленные запросы** — какие отчёты отвечают дольше всего (с момента запуска сервера);
  запросы дольше `SLOW_REQUEST_MS` (5 с) пишутся в журнал с пометкой `[МЕДЛЕННО]`.
* **Ошибки и предупреждения** сервера — последние 100.
* **Блокировки ввода пароля** — компьютеры, которые ввели неверный пароль 10 раз.

## Резервные копии

Включаются строкой `BACKUP_DIR=...` в `server\.env` (лучше другой диск или сетевая папка),
см. `server\.env.example`. Каждую ночь в 03:30: файл `mbs_ДАТА_ВРЕМЯ.sql` (все таблицы
своей БД, хранится 14 дней) и копия фото `uploads\`. Восстановить — открыть файл в любом
клиенте MySQL (например HeidiSQL → «Загрузить SQL-файл») и выполнить на нужной БД.

## Откат

Вернуться к прежнему способу: закрыть окна MBS server и MBS client и запустить, как
раньше, `npm run dev` в `server` и в `client`.
