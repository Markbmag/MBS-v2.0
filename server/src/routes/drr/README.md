# DRR по чекпоинтам

Для каждого чекпоинта два файла:

| Чекпоинт          | Дашборд (маршруты, расчёт DRR) | Снимки смен (фоновое сохранение + история) |
|-------------------|--------------------------------|--------------------------------------------|
| CP5               | `cp5.js`                       | — (снимков нет)                            |
| CP6               | `cp6.js`                       | `cp6-snapshots.js`                         |
| CP7               | `cp7.js`                       | `cp7-snapshots.js`                         |
| CP7 Touch Up      | `cp7-tup.js`                   | `cp7-tup-snapshots.js`                     |
| CP8               | `cp8.js`                       | — (снимков нет)                            |
| ADAS (TLADAS)     | `adas.js`                      | `adas-snapshots.js`                        |
| PIP               | `pip.js`                       | `pip-snapshots.js`                         |
| CPFinal           | `cpfinal.js`                   | `cpfinal-snapshots.js`                     |
| Электроника (BMS) | `electronics-bms.js`           | `electronics-bms-snapshots.js`             |
| WT Portal (старый)| `wt-portal.js`                 | —                                          |

## Что можно править отдельно

* Файл снимков чекпоинта затрагивает только снимки этого чекпоинта.
  Исключение: `cp7-tup-snapshots.js` берёт список постов `CP7_SNAPSHOT_POST_LISTS`
  из `cp7-snapshots.js` — изменение этого списка меняет и снимки CP7 Touch Up.
* Снимок считает DRR теми же функциями, что и дашборд своего чекпоинта
  (например, `adas-snapshots.js` использует функции из `adas.js`), поэтому
  изменение расчёта в файле дашборда меняет и новые снимки — так цифры совпадают.
* `../../lib/shifts.js` — границы смен, буква смены, «последняя завершённая смена»
  и «завершённые сутки». Используется снимками **всех** чекпоинтов: изменение там
  затрагивает всех.

После любого изменения: `npm run harness:verify` в папке `server`
(см. `server/test/harness/README.md`).
